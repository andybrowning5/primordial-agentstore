# Primordial Index — Phase 0 Contract

This is the integration seam for the discovery/supply/storefront roadmap (features 1b
routing, 1c streaming, 3b dev, 3c publish, 4b ratings, 4c storefront). The catalog and
ratings API defined here are the **only** coupling between the three build tracks:

- **index-service** (`primordial-index/`) — crawler + Cloudflare Worker + D1; *produces* `catalog.json` and the ratings API.
- **web-storefront** (`primordial-web/`) — static site; *consumes* `catalog.json` + detail + stats.
- **client** (`packages/client`) — CLI/MCP; *consumes* `catalog.json` for routing, *calls* ratings/telemetry endpoints.

Agents themselves remain pure GitHub repos (`primordial-agent` topic + `agent.yaml`).
The index is a purely additive read/aggregation layer. Backend choice: **Cloudflare
Worker + D1** (writes only); catalog is static, served from R2/KV via the Worker.

---

## 1. `catalog.json` (the seam)

Regenerated by the crawler on a schedule + on publish webhook. Lean — for CLI prefetch
and storefront list views. Full manifest + README live in per-agent detail files.

```jsonc
{
  "schema_version": "1",
  "generated_at": "2026-05-29T00:00:00Z",
  "agents": [
    {
      "id": "owner/repo",                  // GitHub full_name = stable id
      "url": "https://github.com/owner/repo",
      "ref": "v1.2.0",                      // latest semver tag, else default branch
      "commit": "abc123…",                  // resolved commit sha for ref
      "name": "web-research",               // manifest name (kebab-case)
      "display_name": "Web Research",
      "version": "1.2.0",
      "description": "…",                   // <=500 chars
      "category": "research",
      "tags": ["web", "search"],
      "language": "python",
      "author": { "name": "…", "github": "…", "website": "…" },
      "providers": ["anthropic", "tavily"], // from manifest keys[].provider
      "permissions": {
        "network": ["api.tavily.com"],
        "network_unrestricted": false,
        "filesystem": "readwrite",          // workspace mode: none|readonly|readwrite
        "delegation": true
      },
      "trust": "auto",                      // "auto" | "requires_approval" (assess_manifest_trust)
      "signals": {
        "stars": 42,
        "runs_30d": 0,                      // telemetry; 0 until 4b live
        "rating_avg": null,                 // 1-5 or null
        "rating_count": 0,
        "success_rate": null                // 0-1 or null
      },
      "readme_excerpt": "…",                // first ~280 chars, for list cards
      "updated_at": "2026-05-20T…Z",        // repo pushed_at
      "last_crawled": "2026-05-29T…Z"
    }
  ]
}
```

**Per-agent detail** (`/agents/:owner/:repo`, for storefront detail pages): a **superset**
of the catalog entry (all list fields) plus `manifest` (full parsed `agent.yaml`),
`readme_md` (raw markdown — the index does NOT render HTML), and the resolved `signals`.
The storefront renders the markdown and **sanitizes** the result before display (READMEs
are untrusted content). `readme_html`, if ever present, is also sanitized client-side.

Consumers MUST tolerate unknown fields and `null` signals. `id` is the join key everywhere.

## 2. Ratings & Telemetry API (Cloudflare Worker + D1)

Base URL configurable; default `https://index.primordial.dev`. Client override via
`PRIMORDIAL_INDEX_URL` env / config. All write endpoints are rate-limited.

| Method & path | Purpose | Body / notes |
|---|---|---|
| `GET /catalog` | Serve `catalog.json` | `Cache-Control: max-age=3600`. Proxies R2/KV. |
| `GET /agents/:owner/:repo` | Per-agent detail | Full manifest + README + signals. |
| `GET /agents/:owner/:repo/stats` | Live signals | `{ runs_30d, rating_avg, rating_count, success_rate }` |
| `POST /events` | Opt-in telemetry | `{ agent_id, event, success?, duration_ms?, client_id, ts }` |
| `POST /ratings` | Submit a rating | `{ agent_id, stars (1-5), comment? (<=500), gh_token }` |
| `POST /refresh` | On-demand single-agent re-index | `{ agent_id }`. Pinged by `primordial publish`. |

- `POST /refresh` re-indexes ONE repo immediately (no full crawl). Abuse guard: the
  repo must actually carry a configured topic (`primordial-agent`), else it is not
  indexed (`422`). Rate-limited like the other writes. Returns `202 {ok,indexed,id}` on
  success, `422 {ok:false,reason}` if ineligible. Best-effort from the client's side.

- `event` ∈ `"run_start" | "run_complete"`. `success`/`duration_ms` only on `run_complete`.
- `client_id` = locally generated anonymous random UUID stored in client config. **No PII.**
  Used only for dedup/abuse limiting, never identity.
- `POST /ratings` verifies `gh_token` against the GitHub API to resolve the rater's login;
  stores **one rating per (agent_id, gh_login)** (upsert). Prevents spam.

### D1 schema

```sql
CREATE TABLE events (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  agent_id    TEXT NOT NULL,
  event       TEXT NOT NULL,           -- run_start | run_complete
  success     INTEGER,                 -- 0/1, null on run_start
  duration_ms INTEGER,
  client_id   TEXT NOT NULL,
  ts          TEXT NOT NULL            -- ISO8601
);
CREATE INDEX idx_events_agent ON events(agent_id, ts);

CREATE TABLE ratings (
  agent_id   TEXT NOT NULL,
  gh_login   TEXT NOT NULL,
  stars      INTEGER NOT NULL,         -- 1..5
  comment    TEXT,
  updated_at TEXT NOT NULL,
  PRIMARY KEY (agent_id, gh_login)
);
```

The crawler folds `events` (last 30d) + `ratings` into each agent's `signals` when it
regenerates `catalog.json`.

### Privacy
Telemetry is **opt-in** (client config `telemetry.enabled`, default `false`, asked once on
first run). Anonymous `client_id` only. Document in `docs/users/security.md`.

## 3. Client integration points (for the `client` track)

- **Prefetch**: `GET {index_url}/catalog` → cache `cache_dir/catalog.json` with TTL (6h).
  On any index failure, fall back to live GitHub discovery (`discovery.py`). Never hard-fail.
- **Routing** (`recommend_agents` / `primordial recommend`): rank the cached catalog with
  `ranking.py`. Blended score = semantic similarity + popularity (`signals.runs_30d`,
  `rating_avg`) + `stars`.
- **Telemetry hook**: when opt-in, `POST /events` run_start/run_complete around agent runs.
- **Rate command** (`primordial rate <agent> <1-5> [--comment]`): resolve a GitHub token
  (gh CLI / `GH_TOKEN`), `POST /ratings`.
