# Primordial Index

The discovery/aggregation layer for [Primordial AgentStore](../README.md). It is
a single **Cloudflare Worker** that does two jobs:

1. **Crawler** (scheduled cron) — walks the GitHub `primordial-agent` topic,
   validates each repo's `agent.yaml`, resolves the latest semver tag (else the
   default branch) + commit SHA, folds in telemetry/ratings signals from D1, and
   writes `catalog.json` + per-agent detail JSON to **R2**.
2. **HTTP API** (fetch handler) — serves the catalog and detail files and accepts
   opt-in telemetry events + ratings, persisted to **D1**.

This is a purely **additive read/aggregation layer**. Agents themselves stay as
plain GitHub repos (`primordial-agent` topic + `agent.yaml`). The catalog and
ratings API are the only coupling between the index, the web storefront, and the
client — see [`docs/developers/index-contract.md`](../docs/developers/index-contract.md),
which is the source of truth for every field and endpoint here.

## Architecture

```
                       ┌──────────────────────── Cloudflare Worker ─────────────────────────┐
GitHub (topic search) →│  crawler (cron */6h)  ──writes──▶  R2: catalog.json, agents/*.json │
                       │                                                                     │
client / web  ────────▶│  HTTP API (fetch)     ──reads───▶  R2                               │
                       │       POST /events, /ratings ───writes──▶ D1: events, ratings       │
                       │       crawler ───reads signals──────────▶ D1                        │
                       └─────────────────────────────────────────────────────────────────────┘
```

- **R2** (`CATALOG`) holds the generated static JSON. `GET /catalog` and
  `GET /agents/:owner/:repo` proxy R2.
- **D1** (`DB`) holds write-only `events` + `ratings`. The crawler aggregates the
  last 30 days of events and all ratings into each agent's `signals`.
- **KV** (`RATELIMIT`) holds per-IP fixed-window counters for the write endpoints.

## API (contract §2)

| Method & path | Purpose |
|---|---|
| `GET /catalog` | Serve `catalog.json` (`Cache-Control: max-age=3600`). |
| `GET /agents/:owner/:repo` | Per-agent detail: full manifest + README + signals. |
| `GET /agents/:owner/:repo/stats` | Live signals: `runs_30d`, `rating_avg`, `rating_count`, `success_rate`. |
| `POST /events` | Opt-in telemetry: `{ agent_id, event, success?, duration_ms?, client_id, ts }`. |
| `POST /ratings` | Submit a rating: `{ agent_id, stars (1-5), comment? (<=500), gh_token }`. |

- `event` ∈ `run_start | run_complete`; `success`/`duration_ms` only on `run_complete`.
- `client_id` is an anonymous random UUID generated by the client — **no PII**,
  used only for abuse limiting, never identity.
- `POST /ratings` verifies `gh_token` against `GET https://api.github.com/user` to
  resolve the rater's public login, then upserts **one rating per
  (agent_id, gh_login)**. Only the public login is stored — never the token.
- Write endpoints (`/events`, `/ratings`) are rate-limited per IP
  (`WRITE_RATE_PER_MIN`, default 60/min).

## Local development

Prereqs: Node 18+ and npm. No Cloudflare account is needed for local dev or tests
— `wrangler dev` and the test pool use a local [Miniflare](https://miniflare.dev)
runtime with local D1 / R2 / KV.

```bash
npm install

# Provide a GitHub token for the crawler (higher rate limits). Optional for the
# API; required to actually crawl. Copy the example and edit:
cp .dev.vars.example .dev.vars   # then set GITHUB_TOKEN

# Apply D1 migrations to the LOCAL database:
npm run db:migrate:local

# Start the Worker locally (API on http://localhost:8787):
npm run dev
```

Exercise the API locally:

```bash
# Telemetry (opt-in event)
curl -X POST http://localhost:8787/events \
  -H 'content-type: application/json' \
  -d '{"agent_id":"octocat/hello","event":"run_complete","success":true,"duration_ms":1200,"client_id":"anon-uuid","ts":"2026-05-29T00:00:00Z"}'

# Live stats
curl http://localhost:8787/agents/octocat/hello/stats

# Rating (gh_token is verified against the GitHub API)
curl -X POST http://localhost:8787/ratings \
  -H 'content-type: application/json' \
  -d '{"agent_id":"octocat/hello","stars":5,"comment":"great","gh_token":"<your-gh-token>"}'
```

### Running the crawler locally

`wrangler dev` exposes a scheduled trigger endpoint. With the dev server running:

```bash
curl "http://localhost:8787/__scheduled?cron=0+*/6+*+*+*"
```

This runs `crawl()` against the live GitHub API and writes `catalog.json` +
`agents/*.json` into the **local** R2 bucket. Then:

```bash
curl http://localhost:8787/catalog
```

> Before any crawl has run, `GET /catalog` returns `503` (catalog not yet
> generated). The committed `fixtures/catalog.json` shows the exact shape the web
> track and tests can rely on without running a crawl.

## Deploy (requires a Cloudflare account)

> No deploy is performed here — these are the steps for whoever has Cloudflare
> credentials.

```bash
# One-time: create the resources and paste the returned IDs into wrangler.toml
wrangler d1 create primordial-index            # → database_id
wrangler kv namespace create RATELIMIT         # → id
wrangler r2 bucket create primordial-catalog

# Store the crawler's GitHub token as a secret (never in wrangler.toml):
wrangler secret put GITHUB_TOKEN

# Apply migrations to the remote D1, then deploy:
npm run db:migrate:remote
npm run deploy
```

The cron in `wrangler.toml` (`0 */6 * * *`) drives the crawler every 6 hours.
Trigger an ad-hoc crawl in production via `wrangler` (Cron Trigger “Run”) or the
Cloudflare dashboard.

## Security & privacy

- **Opt-in telemetry only.** The client only `POST`s events when the user has
  enabled telemetry; this service never receives data otherwise.
- **No PII.** `client_id` is an anonymous random UUID. Ratings store only a public
  GitHub login. The supplied `gh_token` is used once to resolve that login and is
  never persisted.
- **Input validation** on every write: `agent_id` shape, `event` enum, integer
  `stars` 1–5, comment length ≤ 500, ISO-8601 `ts`.
- **Parameterized D1 queries** everywhere (no string interpolation into SQL).
- **Secrets via wrangler**, never hardcoded (`wrangler secret put GITHUB_TOKEN`).
- Rate limiting on write endpoints to mitigate spam/abuse.

## Keeping in sync with the client

`src/lib/trust.ts` mirrors the known-provider set used by the client's
`assess_manifest_trust` (`packages/client/src/primordial/known_providers.py` +
`security/manifest_safety.py`) so the catalog `trust` field equals what the client
computes locally. If the client adds/removes a known provider, update the
`KNOWN_PROVIDERS` set here too.
